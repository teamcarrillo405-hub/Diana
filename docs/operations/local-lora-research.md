# Local tutoring adapter research

Status, September 28: this signed, permissioned-data 4B experiment path remains unexecuted. A separate CPU synthetic research path has completed five real Qwen2.5-0.5B training experiments with base-model comparisons. All were rejected. The two newest locked a 95% grounding threshold and each reached at most 26/48 mechanical development passes; their independent 100-case final test remains unopened. Blinded semantic review also found substantial quality gaps. See [current grounding evidence](../engineering/grounding-95-results-2026-09-28.md), [initial execution](local-lora-execution.md) and [v2 correction with measured results](local-lora-v2-quality.md). No candidate is approved for students or deployed. The current hosted tutoring route is unchanged. This document's path investigates the [Qwen3-4B-Instruct-2507](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507) candidate under its published Apache-2.0 license; that license does not grant rights to train on unrelated textbook or student content.

## Boundaries

- The existing `buildTrainingExport` gate checks declared training rights, content-bound rights and educator-review receipts, consent for student data, and document/template family separation. These JSON receipts are self-declared. A separate trusted operator must inspect the actual license, reviewer qualification, consent and source evidence before signing the export. Software cannot authenticate those underlying facts by itself.
- `prepare-local-lora.ts` requires each candidate's source text and an exact `source` field in the final user-message JSON payload. That payload accepts only `question`, `source`, and optional `studentResponse`. It checks prompt/source near duplicates against the held-out fixture corpus and writes each reviewed source text beside the conversation in the **private** training JSONL. The manifest contains prompt/source fingerprints and corpus hashes. Python checks the payload/source binding, recomputes fingerprints from actual training rows, and scans every message and nested string value for held-out prompts/sources, including passages hidden inside longer text. The training bytes and manifest are signed separately by an operator-held Ed25519 key. The signer checks the private key, dataset directory and files before reading, then checks an empty attestation file's permissions before writing its signature. Training and comparison require the matching trusted public key and a SHA-256 fingerprint obtained outside the dataset. Editing the dataset or manifest after signing blocks both commands.
- Plaintext export requires private candidate and receipt input files, plus an empty, operator-prepared dataset directory, all outside the source checkout. On Windows, `verify-private-acl.ps1` checks ownership, disabled directory inheritance, current-user read/write access, and that no principal besides the current user, SYSTEM, or Administrators has an Allow rule. The exporter first creates **empty** files and checks their ACLs before writing any training text. On POSIX, the pre-existing directory must be `0700`; all input and empty output files must be `0600`. Python also checks the dataset and requires separately prepared, empty private adapter and comparison directories before output. Any failed check blocks the export or run. These checks do not replace institutional handling rules or disk encryption.
- Export authorization expires within 24 hours. Training and comparison additionally require a fresh, separately supplied Ed25519-signed revocation snapshot, also valid for no more than 24 hours, listing revoked dataset hashes. The operator must update that list from the authoritative rights/consent process before signing. A signed empty list alone is not proof that no consent was withdrawn. The commands check authorization again before saving training output or running comparison; a withdrawal during a run can still leave transient model state in memory, so the operator must stop affected jobs promptly.
- The Python runner sets Hugging Face and Transformers offline flags before importing model libraries, loads only a supplied local safetensors snapshot, sets `trust_remote_code=False`, and never publishes the adapter. No API key or paid provider call is used.
- A local adapter is a Diana-specific artifact, but generic LoRA is not proprietary by itself. Its value must be measured against the unchanged base model and the existing retrieval/teaching pipeline.

## Qualified machine and package environment

Use Python 3.13 in an isolated environment, a BF16-capable CUDA GPU with at least 20 GiB VRAM, adequate host RAM/storage for the 4B checkpoint, and a locally available model snapshot. The VRAM threshold is a conservative admission gate, not a successful-run guarantee. `scripts/learning/local-lora-requirements.txt` pins direct versions. Resolve and archive transitive wheels in the qualified environment, then record their hashes and the installed package inventory for a fully reproducible run. The runner refuses version drift in its direct dependencies and records those versions in its run artifact. Its architecture check matches the [published Qwen3-4B configuration](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507/blob/main/config.json), but an operator must still verify the snapshot came from the intended publisher and record its immutable source revision. [PEFT LoRA guide](https://huggingface.co/docs/peft/en/package_reference/lora), [Transformers model loading](https://huggingface.co/docs/transformers/main_classes/model)

The current Windows machine has 66.2 GB host RAM, 32 logical CPUs, Python 3.14.4 and torch 2.12.0+cpu; CUDA is unavailable. A separate isolated CPU experiment environment now provides Transformers 5.17.0, PEFT 0.21.0 and Accelerate 1.15.0, with an official pinned 0.5B checkpoint downloaded and actually trained. The BF16 CUDA requirements for this document's 4B runner remain unmet. The smaller synthetic experiment does not qualify this machine or its dataset for the signed 4B route.

## Prepare and train

On the qualified private research machine, prepare an empty dataset directory outside the repository. On POSIX give it mode `0700`. On Windows use NTFS, disable ACL inheritance on that directory, and allow Full Control only to the current operator, SYSTEM and Administrators. Run the read-only `verify-private-acl.ps1 -LiteralPath PATH_TO_EMPTY_DATASET_DIRECTORY` check before invoking preparation. Keep the Ed25519 private key outside the workspace in operator-controlled storage. After checking the underlying receipts and exact content, the independent signer records an external review ID and attests the export. `TRUSTED_PUBLIC_KEY_SHA256` is the SHA-256 of the trusted public key's DER/SPKI encoding, distributed through the operator's trusted record rather than read from the editable receipt.

```text
npx tsx scripts/learning/prepare-local-lora.ts PRIVATE_RESEARCH_ROOT/candidates.jsonl PRIVATE_RESEARCH_ROOT/receipts.jsonl PRIVATE_RESEARCH_ROOT/dataset-001
npx tsx scripts/learning/attest-local-lora.ts PRIVATE_RESEARCH_ROOT/dataset-001 OPERATOR_PRIVATE_KEY.pem trusted-operator external-review-001
npx tsx scripts/learning/prepare-local-lora-eval.ts artifacts/learning-engine/research/local-lora/heldout-001
python scripts/learning/sign_local_lora_revocations.py --private-key OPERATOR_PRIVATE_KEY.pem --revoked-hashes PRIVATE_RESEARCH_ROOT/revoked-hashes.json --output PRIVATE_RESEARCH_ROOT/revocations-001.json
python scripts/learning/train_local_lora.py preflight --dataset PRIVATE_RESEARCH_ROOT/dataset-001 --heldout artifacts/learning-engine/research/local-lora/heldout-001 --model PATH_TO_LOCAL_QWEN3_SNAPSHOT --trusted-public-key TRUSTED_PUBLIC_KEY.pem --trusted-key-sha256 TRUSTED_PUBLIC_KEY_SHA256 --revocations PRIVATE_RESEARCH_ROOT/revocations-001.json
python scripts/learning/train_local_lora.py train --dataset PRIVATE_RESEARCH_ROOT/dataset-001 --heldout artifacts/learning-engine/research/local-lora/heldout-001 --model PATH_TO_LOCAL_QWEN3_SNAPSHOT --trusted-public-key TRUSTED_PUBLIC_KEY.pem --trusted-key-sha256 TRUSTED_PUBLIC_KEY_SHA256 --revocations PRIVATE_RESEARCH_ROOT/revocations-001.json --output PRIVATE_RESEARCH_ROOT/adapter-001 --allow-local-training
```

Generate the authored held-out fixtures before preflight with the command below. Prepare empty private adapter and comparison directories outside the checkout before using them; prepare `revoked-hashes.json` as a private JSON array, including every dataset hash with withdrawn rights or consent. The runner requires at least 32 attested examples; that floor only avoids a meaningless technical run and does not establish a statistically adequate tutoring dataset. Its example count must divide evenly by gradient accumulation, so partial optimizer updates are blocked. It masks system and user tokens, trains on the final approved assistant reply, refuses truncation or chat-template misalignment, bounds epochs/steps/sequence length, records base-weight, tokenizer and adapter-file hashes plus optimizer settings, and writes a separate adapter with a run manifest. The actual model behavior and hardware memory fit have not yet been tested.

## Compare without changing student routes

Generate the repository's authored held-out fixtures and compare the *same* prompts using the frozen base and the adapter:

```text
python scripts/learning/compare_local_lora.py --dataset PRIVATE_RESEARCH_ROOT/dataset-001 --eval artifacts/learning-engine/research/local-lora/heldout-001 --model PATH_TO_LOCAL_QWEN3_SNAPSHOT --adapter PRIVATE_RESEARCH_ROOT/adapter-001 --trusted-public-key TRUSTED_PUBLIC_KEY.pem --trusted-key-sha256 TRUSTED_PUBLIC_KEY_SHA256 --revocations PRIVATE_RESEARCH_ROOT/revocations-001.json --output PRIVATE_RESEARCH_ROOT/comparison-001 --max-cases 12
```

The comparison checks the signed export, code-pinned held-out corpus digest, exact and numeric-template prompt/source fingerprints, base snapshot, and saved adapter configuration and weights. It uses greedy decoding with the same prompt and token cap for each arm, saves both outputs, and calculates only format, abstention, source-quote, and exact math-answer diagnostics. It checks authorization again before marking the comparison complete; an expired or revoked authorization leaves an explicit `invalid_authorization` report and unusable partial outputs. Twelve cases is a bounded smoke; use the full held-out set and new educator-authored cases for a credible result. Hashes and near-duplicate heuristics cannot prove semantic independence, and the adapter run report itself is not externally sealed against coordinated tampering. Blinded, qualified educators must assess hint quality, source faithfulness, age appropriateness, and harmful or unsupported responses. A prospective learner study is needed for a learning-gain claim. No automatic score in this script promotes a model or establishes a moat.

## Verification and present blockers

The TS gate tests and Python contract tests for this signed 4B route run without weights. This route remains blocked until authentic permissioned/reviewed examples, an independent export signer and trusted key distribution, a qualified machine, a locally supplied 4B model snapshot, and the pinned environment are present. Keep any candidate adapter in the private research directory until blinded comparisons and safety review support a separate product decision. The separate original-synthetic CPU route has executed real training and saved-adapter comparisons without weakening these requirements.
