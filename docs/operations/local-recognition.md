## Adapter and file contracts

`scripts/learning/recognize-local.ts` is an explicit local evaluation command. It accepts a private manifest, asset path, MIME type and **new** output path. `DIANA_RECOGNITION_PYTHON` must name an absolute Python executable in a pinned environment. The shared runner launches `recognize_local.py` without a shell, strips unrelated environment values, bounds output and ends recognition at two minutes.

The authenticated `/api/learning/local-recognition` route checks for a `localhost`, `127.0.0.1` or `[::1]` URL with `DIANA_LOCAL_RECOGNITION_ENABLED=1`, and it is disabled in Vercel. **The operator must bind the enabled Next process to `127.0.0.1` or `::1`, or enforce equivalent network isolation.** A remote HTTP client can spoof Host and Origin headers, so the route's URL and Origin checks do not establish that a request came from the local machine. POST requires a same-origin `Origin`, an active learning capability, one available process slot and a bounded multipart upload. GET checks that the Python executable, approved/unexpired manifest and every listed model file exist. GET does **not** hash or load model weights; POST performs full file-hash verification in the Python adapter before and after inference. Both methods also require a successful signed challenge against `learning_recognition_provenance_ready`; this confirms that the database has the same signing key before any draft is offered. The response discloses no private paths. Configure these absolute paths in the local server environment only:

```
DIANA_RECOGNITION_PYTHON=<pinned Python executable>
DIANA_RECOGNITION_SPEECH_MANIFEST=<private Whisper manifest JSON>
DIANA_RECOGNITION_HANDWRITING_MANIFEST=<private TrOCR manifest JSON>
DIANA_RECOGNITION_PROVENANCE_KEY=<64 or more hexadecimal characters from a secret random generator>
DIANA_LOCAL_RECOGNITION_ENABLED=1
```

Generate the provenance key locally with a cryptographically secure random source, store it only in the local server environment, and keep it distinct from Supabase and provider credentials. The reviewed migration `20260928043131_learning_recognition_provenance_guard.sql` is applied to the production-linked database (September 27 local time). Its signing key requires separate provisioning. Provision the **same decoded key bytes** into the single row of `diana_private.learning_recognition_key` using a secure administrator connection and a bound parameter. The migration deliberately contains no key. Do not put the key in a SQL migration, shell history, browser console or application logs. The database schema and key table are inaccessible to the student role; the challenge RPC returns only a boolean. A missing or mismatched key keeps local recognition unavailable. Only set the enable flag after reviewing the manifest, licenses, test results and host isolation. Restart the local Next server after changing environment variables. Do not place manifests or model snapshots under `public/` or commit private student samples. In Course Practice, a student can supply a WAV file or a cropped line image; Diana puts the tentative transcript in the response field and requires the student to check the original and confirm it. Manual input remains available. Math notation, diagrams, long pages and arbitrary microphone formats are outside this adapter's supported input.

The manifest contains `model`, `directory` and `files`. `model` must satisfy `recognitionModelSchema`: kind, model ID, exact publisher revision, file-map hash, operator/model approval reference, time, expiry and enabled status. `files` maps every file in the private model directory to its SHA-256. The file-map hash is SHA-256 of canonical JSON with sorted keys, UTF-8 and compact separators. There are no nested directories, outside symlinks or unlisted files. The manifest is reread before output is released; model files are also rehashed after inference.

Only local model paths are loaded. Hugging Face offline flags, `local_files_only`, `trust_remote_code: false`, safetensors-only handwriting weights and a Python socket denial prevent ordinary network fallback. OS-level network isolation was not measured. The speech adapter uses CPU/int8 with two threads; its smoke used an isolated Python 3.12 environment with `faster-whisper` 1.2.1. The handwriting smoke reused the existing Python 3.14 CPU environment read-only. Package and model acquisition were separate from inference. [faster-whisper usage](https://github.com/SYSTRAN/faster-whisper), [TrOCR model card](https://huggingface.co/microsoft/trocr-base-handwritten)

Inputs are at most 5 MB: PNG/JPEG containing a single horizontal handwriting line, or 16 kHz mono PCM16 WAV up to 120 seconds. Image decoding is bounded at four million pixels; output text is bounded at 4,000 characters. The Python adapter applies EXIF display orientation, then conservatively rejects square or taller-than-wide crops with `recognition_unsupported_layout` at the process/CLI boundary. This does not detect multiple lines in wide images, and a narrow single-character crop may require manual entry. The local HTTP route retains its neutral unavailable/manual-entry fallback. The parent process needs OS memory supervision in a production deployment; file and time limits alone do not bound neural-model RAM.

## Confirmation and evaluation

`recognition.ts` binds the output to the source asset, model revision and all model files. Confidence is unknown, not a fabricated calibrated probability. Recognition starts unconfirmed. The local route signs the student ID, exact transcript hash, source asset hash, model identity, revision and file-map hash with a 15-minute HMAC proof. Course Practice verifies the proof on the server before it saves a `machine_interpretation` response with durable recognition evidence. The database trigger rejects a new machine response without a matching proof even if a signed-in client calls `learning_save_problem` directly. It also rejects machine claims outside the response on class-scoped records. Assignment tutoring has its own machine-made prompt/source observations and remains outside this recognition proof contract. A transcript edit drops the proof and becomes student-entered text; a saved unchanged machine response retains its evidence when reopened. Unchecking confirmation clears the saved response confirmation. The existing typed/manual path and historical records without recognition evidence remain valid. This guard covers the machine response claim in class practice only; other client-provided notebook fields such as authorship and confirmation remain outside this proof's trust boundary. The saved evidence records `networkUsed: false` and `confidence: null`; it does not claim accuracy, educator review or calibrated confidence. Broader notebook/upload integration remains open.

The unmodified `20260925201612_learning_problem_records.sql` migration, the recognition migration, and `scripts/learning/test-recognition-real-schema.sql` were exercised in sequence on a temporary isolated PostgreSQL 16 database, after `scripts/learning/test-recognition-schema-setup.sql` supplied the earlier auth/class/document table dependencies. The test invokes the actual authenticated `learning_save_problem` RPC and rolls back its rows and synthetic key. It checks missing and matching key readiness, ordinary manual responses, valid proof and unchanged revision, and rejection of unproved, edited, forged and non-response machine claims. It also checks that an assignment tutoring prompt can still be saved. `test-recognition-provenance.sql` is a narrower trigger-unit fixture with a simplified table and must not be treated as the actual-schema test. This is database contract testing, not recognition accuracy evidence. The migration has not been applied to shared staging in this workstream.

`scripts/learning/evaluate-local-recognition.ts` runs the same offline adapter sequentially over a private JSONL manifest of `mediaCaseSchema` test cases. It requires approved cases with two independent reviewer IDs, pinned asset hashes and consent/license receipts, then writes a **new** metrics-only report with character and word error rates, critical math-symbol sequence agreement and per-case latency. Example:

```
node --conditions=react-server --import=tsx scripts/learning/evaluate-local-recognition.ts <private-cases.jsonl> <approved-model-manifest.json> <new-report.json>
```

The report omits raw recordings, images and transcripts. Evaluate representative permissioned samples from multiple ages, accents, handwriting styles and devices; independently review critical sign/unit errors, unsupported math and diagrams, memory use and fallback behavior. Do not use adapter contract tests as accuracy evidence. The current adapters have not established performance, fairness, calibration or production availability.
